# 外部管理 API：配置、部署与恢复

本说明依据当前代码路径编写。本轮只实施本地模拟验收，不部署、不操作真实账号。不要把本文作为线上已经升级的证明。

## 最少配置

管理 Key 不使用环境变量批量填写，不与模型 `API_KEYS` 共用，也不需要额外的默认变量。

- 保留既有模型 `API_KEYS`。
- 使用已配置的 `WEB_CONSOLE_PASSWORD` 登录控制台后，在设置中的管理 Key 面板发行密钥。未配置控制台密码时，旧模型 Key 登录仍能使用原控制台，但不能发行管理 Key；需要启用此功能时才补充控制台密码。
- 管理调用只发送 `Authorization: Bearer mgmt_...`，模型调用仍使用模型 Key。
- 不要把管理 token、模型 Key 或凭证写入 Git、URL 查询参数、截图或测试记录。新 token 仅创建时显示一次；丢失后撤销并重建。
- 原端口、浏览器路径、模型配置及环境变量优先级保留。默认配置不要重复填写。

## 构建与发布边界

当前源码仍通过仓库的 Dockerfile 构建，管理模块位于 `src`，前端组件由现有 Vite 构建过程包含；没有额外进程、数据库、暴露端口或管理专属必填变量。

GitHub 源码部署应使用包含本次最终集成提交的分支，而不是尚未集成的子任务分支。先在测试实例完成真实双账号验证，再安排生产发布。本轮不推送分支、不触发云部署。

管理鉴权校验、JSON 大小限制和管理路径的 404/405 在模型转发前结束。未知管理路径不能落到上游模型代理。控制台管理 Key 写操作需要密码来源 Session 和同源保护；不能拿管理 Key 调控制台发 Key 接口。

## 必须持久保存的内容

|容器路径|用途|注意事项|
|---|---|---|
|`/app/configs/auth/`|当前账号凭证及启禁用标记|敏感 Cookie，不公开共享|
|`/app/configs/runtime-settings.json`|既有可持久化设置子集|保留原路径/加载优先级；不是所有运行时开关都持久化|
|`/app/data/management/`|账号稳定 ID/版本/编号墓碑、管理 Key 摘要、任务/幂等/审计、归档|必须与凭证一起备份与恢复，不能只复制 auth 文件|
|`/app/data/` 其余既有文件|用量、路由状态、AutoHeal 历史备份等|保留原部署的数据卷|

只持久化 auth 卷不够：重建实例时会丢失管理 Key、任务记录、稳定 ID 和不可复用编号。目录卷平台可持久化 `/app/configs` 与 `/app/data`；挂载整个 configs 前必须从当前实例备份并填充已有配置（含模型配置），避免空卷遮蔽镜像内文件。支持单文件挂载的平台也可继续单独保留 runtime-settings 文件；测试覆盖了文件替换受限的原位写回退，但此回退不提供掉电瞬间的原子性保证。

权限限制依靠运行用户和受限文件权限；管理 Key 只保存摘要，Cookie、归档及任务私有输入仍是可读取的敏感凭证，不是加密保险箱。限制数据卷读取者并使用部署平台的磁盘/备份加密能力。

## 单进程限制与迁移

当前文件存储适用于单进程、单副本。不要让多个副本共用同一配置/数据卷，也不要多开进程并发写这些文件。需要扩容时应先迁移到具备事务和跨进程锁的存储，不能直接增加副本数。

运行中的维护统一走控制台或管理 API。`scripts/auth/saveAuth.js` 已统一使用 CredentialStore 分配编号，但仍是离线作者进程，保存前必须停服；不可同时与服务写同一卷。

首次启动为旧凭证分配稳定身份/版本，不重编号、不擅自删除非法旧文件。删除后的墓碑与高水位编号保留；归档恢复维持身份，并保持禁用，需明确后续操作。旧控制台有效请求和模型鉴权机制保留。

## 重启与恢复

1. 停止接受新管理写操作，正常关闭实例，备份 configs 与 data 的一致快照。
2. 升级源码并使用同一份持久卷；不要只恢复部分 credentials 元数据。
3. 启动后确认管理 Key 可用、凭证状态/版本、任务状态、持久设置与原有用量信息。
4. 排队任务在处理器注册后恢复；上次运行中的任务记录为 interrupted，不能自动重放可能已发出的模型请求。查询逐项结果后，再决定是否提交新的逻辑任务。
5. 重试同一次提交保留原 Idempotency-Key；换请求内容时使用新 Key，避免把有冲突的重试当作新操作。

回滚时同时恢复升级前的代码与一致数据快照。不要在不了解新版元数据的旧代码中继续复用编号、绕开写入入口。

## 验收

运行 `npm run test:management` 与 `npm run build:ui`。模拟测试使用临时目录、虚构账号和 loopback，不等于 Google 真实认证或真实模型成功。本轮用户已要求将真实双账号测试另行安排；完整记录见任务台账和最终验证记录。

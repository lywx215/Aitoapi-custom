# 单账号与批量凭证测试

本任务于 2026-09-28 收到正式 Claude 审核触发指令；本文件是该次审核及后续开发的当前计划。审核通过后直接执行下述实现与验收步骤。

## 已确认需求

- 将账号管理页“批量检测”升级为“批量凭证测试”，“测试账号连接”升级为“凭证测试”。
- 单行按钮测试对应账号；批量按钮仅测试选中的账号，支持跨页选择。
- 必须启动指定账号的会话，实际调用 gemini-3.8-flash 并获取有效模型正文回复；不能把连接成功当作模型测试成功。
- 禁用、过期账号允许测试；成功后自动启用，失败保持原状态。
- 后端持续执行批次，离开或刷新页面后仍可恢复查看进度及结果。
- 用户要求先经 Claude 计划审核，通过后自动开始开发，无需再次请求开发指令。
- 本次范围为本地实现及验证，不包含部署、生产账号调用、提交或推送 Git。

## 功能与交互

- 两种按钮共用同一测试流程。逐账号展示进度、模型回复、耗时和失败原因。
- 无效、重复、已删除账号跳过并说明原因。禁用、过期账号不再被前端直接跳过。
- 按钮旁提示“实际调用模型，成功后自动启用”；点击直接开始，不增加确认弹窗。
- 页面每两秒读取进度，重新进入自动恢复查看。支持仅重试失败账号。
- 重试集合固定为模型/身份/启动/超时等验证失败以及尚未验证成功的重启中断项；按 modelVerified 区分中断阶段，验证成功后在启用/刷新阶段中断的项排除。还排除已删除账号、skipped、停止后未执行、version_conflict、验证已成功但启用保存或刷新失败项。后一类显示人工刷新/检查账号状态提示，不以“重试失败”重新消耗模型调用；仍可由用户再次主动选择账号发起新测试。独立测试核对重试索引集合。
- 停止操作表示停止后续账号，当前账号完成后结束。未执行账号明确标记，不算测试失败。

## 后端执行

- 新增控制台凭证测试任务服务，复用 ManagementVerifier 的隔离浏览器、身份校验、模型调用和资源清理能力。
- 复用类但为控制台服务创建独立 ManagementVerifier 实例，不与管理 API 共享 tail 队列；只在本批次当前账号开始时调用 verify，十分钟预算不包含批次等待。页面明确显示待执行/启动/验证/启用阶段；测试并行存在管理 API 验证时控制台不耗费预算排其队。
- 每个账号使用自己的凭证启动隔离会话，固定模型 gemini-3.8-flash，发送固定提示词 `Reply with exactly OK.`。
- 不切换其他账号重试，不回退其他模型，不主动切换控制台当前账号。
- 成功必须满足身份匹配、上游成功状态、模型匹配、正常结束并包含非空正文。仅连接成功、空响应、仅思考内容、截断回复均失败。
- 预期身份必须是凭证 accountName 或存储元数据 accountName 中的有效邮箱，缺失时报告 identity_unverifiable，不调用模型且不启用。传入验证器的 accountName 固定为预期邮箱。
- 扩展验证结果，返回经过校验的正文摘要，最多 2,000 字符，前端纯文本展示。保持原有管理 API 验证语义及调用方兼容。
- VerifierTransport 从通过校验的 STOP candidate 提取所有非 thought 的 text，截取前 2,000 字符到实例属性；generate 仍返回 HTTP 状态码。ManagementVerifier 仅在可信内部参数 includeResponseText=true 时附带摘要，管理 API 默认不启用该参数，ManagementTaskService 继续仅保存既有白名单字段。增加默认结果结构与显式摘要两种兼容测试。
- 验证及资源清理成功后，若测试开始时账号为禁用或过期，使用凭证版本和状态版本双条件更新，清除禁用、过期及禁用原因，刷新账号池。此恢复分支的任一版本变化均报告冲突，不覆盖人工操作。
- 若测试开始时账号已经启用，成功后重新读取元数据：仅要求账号仍存在、accountId 相同、stateVersion 未变且仍为启用状态；不调用 updateState，不检查 credentialVersion。这样在线浏览器例行 mergeStorageState 刷新 Cookie 不会造成无写入操作的假冲突。该结果明确表示所捕获凭证快照的模型验证成功，返回测试时的 credentialVersion；若当前凭证版本已变，额外显示“凭证已更新，此结果对应测试时快照”，不宣称新凭证已验证。该分支不刷新账号池。
- 测试期间人工禁用、过期、删除或归档仍报告 version_conflict。真实凭证替换如果只改变 credentialVersion，在已经启用分支同样显示快照提示；在需要恢复启用分支仍严格拒绝旧版本写入。
- 保留既有冷却记录和其他模型限流状态。测试失败不自动禁用原本启用的账号。
- 成功后自动启用是本次用户明确选择的人工恢复语义，同样适用于 quota_exhausted、crash_loop、401/403 自动禁用；不清除路由冷却或历史熔断计数。AutoHeal 已用凭证/状态双版本条件更新，测试也使用相同机制：先完成者更新状态，后完成者返回版本冲突，不覆盖新状态；增加与 AutoHeal 条件更新竞争的测试。
- 启用保存或运行时刷新失败，分别展示“模型验证成功”与启用/刷新失败，不能误报全部成功。

## 后台任务与接口

- 使用控制台现有登录鉴权，不要求浏览器持有管理 API Key。
- `POST /api/account-credential-tests/runs` 接收 `{ indices, clientRequestId }`，返回 HTTP 202 和任务标识。
- `GET /api/account-credential-tests` 返回当前任务及最近一次完成结果。
- `POST /api/account-credential-tests/runs/:runId/stop` 停止后续账号。
- 单账号使用长度为 1 的列表提交。旧 `/api/accounts/:index/test` 连接测试接口保持原语义，页面改用新接口。
- 全局同时运行一个凭证测试批次，逐账号串行执行；单账号沿用十分钟超时。
- 相同提交标识和相同去重后索引列表返回原 runId、不重复执行；同标识但列表内容或顺序不同返回 HTTP 409 IDEMPOTENCY_CONFLICT，其他并发提交返回忙；对请求参数、账号索引及任务标识进行校验。
- 单批最多 1000 个账号；提交去重记录保留 30 天、最多 1000 条，提交前清除过期记录，满额拒绝新任务，不提前淘汰仍有效记录。公开结果只保留当前批次和最近完成批次，旧 runId 的去重收据不包含完整结果。
- 参考现有 ModelProbeService 的后台任务和原子持久化方式，持久化进度和结果，不保存凭证副本、Cookie 或 Key。
- 服务重启将未完成任务标记为中断，保留已完成结果，不自动重放模型请求。服务关闭时停止调度并清理资源。

## 验证与验收

- 后端覆盖指定账号归属、成功正文、空响应、截断、模型不匹配、401/403/429、启动失败、超时及资源清理。
- 状态覆盖成功自动启用、失败不变、凭证替换或人工禁用触发版本冲突、启用保存与刷新失败。
- 增加已经启用账号测试期间 mergeStorageState 刷新 Cookie 的用例：credentialVersion 增加但 stateVersion 不变，验证仍成功、无状态写入并显示快照提示；同时覆盖人工禁用、真实凭证替换、禁用账号 Cookie 刷新三种分支，确保自动启用仅发生于双版本匹配时。
- 批量覆盖串行执行、失败后继续、重复提交、停止后续任务、刷新恢复及重启中断。

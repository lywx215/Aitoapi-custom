## 实施要求

1. 可安全重试的生成 429 必须重新选择合格账号，与 IMMEDIATE_SWITCH_STATUS_CODES 是否包含 429 无关。仍遵守清理确认、工具副作用限制、总尝试次数与原有请求截止时间。无合格账号则停止重试，不派发给冷却账号。
2. 同请求重试与新请求共享备用加载。处理器级串行覆盖选择候选、源上下文以及预热；等待后先重查是否已有合格连接，避免多请求对同一备用重复替换不同源。候选排除不可用、维护、崩溃隔离、对应模型冷却及启用中的使用次数耗尽限制。
3. 有界池复用 BrowserManager 池锁：replaceOnlyWhenFull 在锁内检查目标是否已存在及池容量；已有空位只加备用，目标已存在则复用，不关闭源。需要替换且源仍为当前账号时，activateIfSourceCurrent 将当前指针转至就绪目标；若指针已改变则不抢回当前指针。新上下文失败不关闭源，源有队列时延迟关闭，排空后可关闭。其他调用者保留默认替换语义。
4. maxContexts=0 只加载备用，不因模型冷却关闭源。账号级禁用/熔断可按既有策略关闭其上下文。账号禁用清理与有界池替换共用池锁，最终请求绑定必须经过目标模型筛选。
5. 浏览器恢复后重选必须带模型；无合格账号返回 503，不回退全局当前账号。更新请求绑定和后续就绪检查使用的 targetAuthIndex。
6. 备用串行队列支持请求 signal 与 deadline：等待者超时/取消立即返回 false（HTTP 层沿用 504/客户端取消），排队工作取得执行机会时再次检查取消，已取消则不初始化上下文、不改绑定。若初始化已开始，可让现有有时限的浏览器初始化完成并供其他请求复用；它仍占有串行队列直到完成，不能因请求取消提前放锁。取消后调用方不得重新绑定账号或继续派发。GenerationPipeline 把现有 signal/deadline 传入重试路由；readiness 外层的关闭/超时同时触发其路由 signal。非生成既有调用方没有 signal 时保持原语义。
7. 请求进入时记录模型，初始账号仅来自实际绑定；零次尝试无最终账号，实际重试使用最后一次尝试账号。管理 usage 同样不回填零尝试账号。历史 JSONL 不重写，不增加标准模式高频诊断。
8. README 明确模型冷却与旧账号熔断的不同路径；只修改相关说明，保留其他任务改动。
